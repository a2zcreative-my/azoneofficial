# Claude Implementation Contract

Read this file before making any implementation change in this repository.

## Required preflight

1. Read `docs/PROJECT-STATE.md`, `CHANGELOG.md`, and the relevant module documentation.
2. Run `git status --short` and inspect `git diff --stat` before editing.
3. Treat uncommitted changes as active work owned by another contributor unless the user explicitly says otherwise. Preserve them and do not overwrite, rename, delete, or reformat those files casually.
4. Check the latest `CHANGELOG.md` entry and the deployed version in `docs/PROJECT-STATE.md`. Do not describe local work as deployed.
5. Search for an existing implementation before adding a new component, route, migration, guard, or CSS token.

## Coordination rules

- `docs/PROJECT-STATE.md` is the current handoff record. Update it when implementation status, release blockers, migrations, or deployment state changes.
- `CHANGELOG.md` records user-visible or operational changes. Add an `Unreleased` entry before a release-related change.
- Do not work in the same files as another active contributor without first reading their diff and preserving their intent.
- Do not create duplicate migrations, tabs, guards, design tokens, or API routes. Check registries and parity tests first.
- Hankeis/Telegram is currently an API contract and offline simulator. The Telegram bot, webhook, file forwarding, and outbox consumer are not part of this repository yet.
- A receipt never verifies a payment. Only an authorised staff reviewer who checks the bank record can verify one.

## Release rules

- Use `PUSH.bat` as the only normal release entry point.
- `PUSH.bat` performs a strict clean-worktree preflight before installing, cleaning, migrating, committing, or deploying. Do not bypass it by calling Wrangler directly.
- If a dirty-tree release is genuinely approved, use `PUSH.bat allow-dirty` and record the approval in `docs/PROJECT-STATE.md` first.
- A failed guard, type check, migration check, or health check means the release is not verified. Never claim deployment from a partial run.
- Production includes the responsive portal release at `v1.168.0`; `PUSH.bat allow-dirty` completed every gate and the production health check on 20 September 2026.
- The `v1.168.0` portal reorganises `/portal` for responsive PWA/web use without changing the existing colour palette. Preserve the existing `canSeeTab`/`accessOf` permission source and the audited `/staff/tabs/access/person` API; do not create a second permission model. Treat the reference screenshots as information-hierarchy inspiration only, not as an instruction to copy their blue palette or replace the existing authenticated login with a PIN.
- Local `v1.169.0` is an unreleased interface-system pass: portal action buttons use the global `.erp-button` 44px pill contract on both breakpoints, icon-only actions use `.erp-icon-button`, and the Dashboard uses one shift hero plus one tabbed Tasks/Leave/News overview. Extend these shared classes instead of adding another hand-written button shape.
- `v1.176.0` — **one home per workflow.** Every workflow completes in exactly ONE place, and every other surface may only summarise it and link. The Desk (`components/portal/desk-page.tsx`) is a real tab in `ALL_TABS` and `ALWAYS_VISIBLE`, never a Dashboard anchor — **a page header must name the destination the person chose**, and the phone bar's manager stop carries a tab with no anchor. The Dashboard renders `DeskSummary` (figures + two preview rows + one link), never the queue; **Tasks owns the task list** and the Desk's task zone is a count and a button; the bell is notifications with read/unread and links, **never a second approval queue**. Guard #71 fails a Desk body that renders a task list, and #94 fails a Dashboard that imports the queue.
- `v1.176.0` — **`sub` is what the item IS; `next` is what YOU do.** `worker/src/desk.ts` must never print an instruction in a status line: an overtime item is `both punches recorded, undecided` with `next: approve or reject`, not "approve or reject" twice. A count that appears on two surfaces comes from ONE `useCachedApi` path (`useDeskData()` = `/staff/desk`), so the two can never disagree; after an action, bump the affected version with `applyVersions` and refresh. **Never combine distinct approvals because they concern the same person.** Repeated findings of the SAME rule group into one expandable line with a count (`WatchersCard section="findings"`); rule configuration is `section="rules"`, at the foot of the page, out of the queue.
- `v1.176.0` — **On Shift is one status and one action.** One chip states the current state (`On shift · clocked in at 08:06` / `Clocked out · 08:06 → 17:12` / `Not clocked in yet`) and one enabled control follows it; a timestamp is printed once, a disabled button is not a status, and the geofence control and its verdict exist once. **Appearance is not a reason to change a rule** — early clock-in, overtime, geofence and payroll logic are untouched by any layout pass.
- `v1.175.0` — **the dashboard's reading order is a MAP, not a sequence in a file.** The five zones (`day`, `desk`, `month`, `company`, `around`) are named elements in `components/portal/dashboard.tsx`; `DASHBOARD_ZONES` says which order each job reads them in (`business` / `sales` / `shift`), and the job is chosen by role AND by what the person may open (`canOpen`). **Re-ordering must never grant anything** — every zone keeps its own gate, which is why the layout is a list of elements and not a second set of role checks. A new zone is added to the five names and to all three orders; guard #71 fails a map that drops one. On Shift keeps a phone-bar stop for every role: the clock is always one tap, whatever the order.
- `v1.175.0` — **One Desk splits decisions from your own work, and acts on exactly one row.** The worker (`worker/src/desk.ts`, still a pure read) sets `kind`, `who` and `next` per item. THE EVIDENCE RULE for any future inline action: a desk row shows a title, a status and a waiting time — enough to TAKE an unclaimed enquiry (not an approval, and reversible), never enough to approve leave, a claim, overtime or a punch, whose evidence lives in the record. Those rows link. A second `takeable` bucket fails guard #71.
- `v1.175.0` — **pins are a preference the existing navigation reads, never a new menu.** `lib/favourites.ts` keeps six per account (`azone-pinned:{userId}`) in the person's order, surfaced through the More sheet, the command palette and the phone bar. Every read is clamped through the shell's own `canSeeTab` list; the stored list is left alone so restored access brings a pin back. **The phone bar never reads a count** — a stop must not move because work arrived overnight — and a stop may be a tab PLUS an anchor (the manager's Desk stop is the Dashboard at `id="one-desk"`), which is how One Desk is reused instead of building a second inbox.
- **The browser checks live in `tests/browser/`.** Fixtures, a fixture server (`ROLE=` swaps the signed-in role), the WebKit overflow probe and the shredding probe, with a README. Add a fixture row for every endpoint a new card reads — an empty card makes every sweep honestly clean — and give the rows the company's real shape of data.
- `v1.174.4` — **a table cell breaks on WORDS, never `anywhere`.** `overflow-wrap: anywhere` is right on `.erp-card` (an unbreakable run wraps inside the card) and destructive inside a table: it drops a cell's MINIMUM content contribution to one character, so the automatic layout may squeeze the column to one character wide - the CEO's Attendance register came out as S/T/A/F/F down the page. Cells are `break-word` (`styles/erp-v3.css`); never put `anywhere` back on a `th`, `td` or table selector, in the sheet or in a module - guard #94 fails it. An **identifier** in a table that already scrolls - a person's name, an account code, a document reference - is `tdOneLine` / `thOneLine` (`white-space: nowrap`): one row, one line, and the reader scrolls. Numbers are `tdR2` / `thR2`, which already nowrap.
- **A width sweep cannot see shredding.** When text is broken *inside* its own column nothing overflows, so `wk-probe.py` correctly reports 0. Run `xvfb-run python3 /opt/node-tools/table-probe.py` as well after any change to wrapping, table or card CSS: it measures every cell against the longest word it holds.
- `v1.174.3` — **a row's actions wrap, and are never pinned.** A row is `.erp-row-lead` (the words) + `.erp-row-actions` (the controls) - the group wraps, shrinks, and breaks left on a phone / right from 640px. NEVER put `shrink-0` on a group that wraps: a flex item that may not shrink is sized by its **one-line max-content**, so its own `flex-wrap` never acts - that is what cut the Sales rows at "Report li" and ran the Attendance overtime buttons off the CEO's phone. A note or search field among the actions is `.erp-input-sm` and the system shrinks it; the date family is excluded because an EMPTY date/month/time control collapses on iOS and keeps a width floor instead. An empty date control also shows its `placeholder` (iOS draws nothing inside one). A wide table that must scroll sideways adds `.tbl-sticky-lead` so its first column pins - a figure the reader cannot attach to a name is not readable. Guard #94 holds all of it.
- **A clean overflow sweep means NOTHING if the card rendered empty.** Before trusting a probe, check the fixture actually serves rows for the card you are testing - `/opt/node-tools/snap2.mjs` - and that the rows carry the CEO's real shape of data (long Malaysian names). Two of the four bugs above sat behind endpoints the fixture did not know.
- `v1.174.2` — **an elevated surface sits on the PAGE.** A sheet, modal, menu or toast (`.erp-sheet`, `.erp-modal`, `.erp-menu`, `.erp-toast`) reads with the page's tokens whatever surface opened it: `:root` captures them as `--erp-page-*` and those four classes re-anchor to them (`styles/erp-v3.css`, *elevated surfaces sit on the PAGE*). Reason: custom properties inherit through the DOM, not the stacking order - a `position: fixed` toast rendered from inside the navy shift hero took the hero's `--card: 6% white` and came out as a ghost band on the CEO's phone. Rules: a surface that carries its own tokens (`.erp-shift-hero`, `.erp-action-bar`) is never "fixed" by flattening it; a new overlay is one of those four classes (or re-anchors the same way), never a `var(--card)` box of its own; a toast has a `max-width` - it is a card in the middle of the screen, not a band. Guard #92 holds all of it.
- `v1.174.1` — **no grid blowout on a phone.** A grid track is sized by its widest item, and an inner scroller does not shield it: the deployed v1.173.0 Ecommerce body (`display: grid`, implicit `auto` track) grew to a card's `min-w-[560px]` table and every card ran off the iPhone. A tab body is `TabPage` (block flow), never a grid; every `display: grid` in a module names its tracks with `minmax(0, …)` or a length - never a bare `1fr` (= `minmax(auto, 1fr)`) or an implicit track; a zone, stack or card that can be a grid/flex item has `min-width: 0`; a wide table lives in a scroller inside a BLOCK card. Guard #94 fails a module grid without named tracks. Verify phones in **WebKit** as well as Chromium: `xvfb-run python3 /opt/node-tools/wk-probe.py` (WebKitGTK, in the sandbox) walks every tab and reports anything past the page's content box - the document `scrollWidth` cannot see a spill the shell clips.
- `v1.174.0` — **roles and responsibilities** live on the staff record (`users.role_title`, `users.responsibilities`, migration 0137) and are written ONLY through `PUT /staff/users/:id/responsibilities` behind `PERMS.responsibilities_edit` (super_admin, admin, hr_admin, ceo) — never as a field on `PATCH /users/:id` (that form's fill-once lock is the wrong rule for a job description). The page passes the same four roles as `canEditResponsibilities`; `tests/staff-responsibilities.mjs` (#95) holds the two lists equal. Working staff only; a leaver's text stays readable. The person reads theirs on Profile and cannot write it.
- `v1.173.0` — **every tab follows the tab concept** (`docs/INTERFACE-SYSTEM-V3.md` §8; guard #94 `tests/tab-concept.mjs`). A tab body is `<TabPage>` of `<TabZone label=…>` sections (`components/portal/tab-concept.tsx`), in the order figures → work → records → setup; the figures are a `SummaryStrip` of `SummaryStat`s (or a `StatStrip` of `StatTile`s) derived from rows the panel already holds, each a button when it filters something, `busy` until known; several things on one topic go behind `SectionTabs` / `PillCard` with panes hidden, never unmounted; a chooser wears `tabPill` / `tabPillOn`, never a hand-rolled pill. A new tab, or a new card on a tab, goes into a captioned zone — the guard fails a bare stack at a tab's root. Layout only: the concept never adds a request or changes a rule.
- `v1.172.2` — **Tailwind is retired** (`docs/INTERFACE-SYSTEM-V3.md` §0 says how to build UI now). No `tailwindcss`, `@tailwindcss/postcss`, `tailwind-merge` or `prettier-plugin-tailwindcss` may return; no `@import "tailwindcss"`, `@theme`, `@apply` or `@custom-variant` in any stylesheet; `cn()` is `clsx`. Styling is: the vocabulary in `lib/ui-styles.ts` → `.erp-*` classes in `styles/erp-v3.css` (surfaces, controls, chips, table chrome, shell, and the layout / type primitives: `erp-flex*`, `erp-stack`, `erp-cols-*`, `erp-icon*`, `erp-text-*`, `erp-meta`, `erp-heading`, `erp-mt-*`), semantic tokens from `globals.css` (never a hex in a component), and a **CSS Module beside the component** for a screen's own layout. **Never write a utility class** (`flex items-center gap-2`, `mt-2`, `md:hidden`): nothing generates CSS for it, and `tests/tailwind-retired.mjs` (#93) fails the build on a utility that `styles/legacy-utilities.css` does not define. That sheet is the utilities the unmigrated screens still carry, FROZEN and shrink-only: never add to it; when a screen migrates, `node scripts/prune-legacy-utilities.mjs --write` then `node tests/tailwind-retired.mjs --write-budget` (the per-file budget in `tests/legacy-utility-budget.json` may only fall; the migrated surfaces stay at zero). `AppIcon` is 16px by rule (`erp-icon-sm/-md/-lg` to resize); stacks are block flow (`erp-stack`), not grids.
- `v1.172.1` — **Portal Interface System V3** (`docs/INTERFACE-SYSTEM-V3.md`). Surfaces, forms, chips, table chrome, the shell and the drawer are named classes in `styles/erp-v3.css`, and `lib/ui-styles.ts` resolves to them. New portal UI takes a name from `lib/ui-styles.ts` or a class from `erp-v3.css`; it does not spell a card, a control, a chip or a button out by hand, and it never states a colour outside `globals.css`. `tests/interface-v3.mjs` lists the migrated files and fails the build if one slides back. Reconciliation, Ads Fund and Purchasing are retired (v1.172.0) and the same guard keeps them out of every registry.
